# 生年月日系占い(7占術)追加と画面構成リニューアル 設計書

- 作成日: 2026-10-14
- ブランチ: `feature/birth-fortune`
- デザイン: Claude Design プロジェクト `4e8bfa69-391c-4206-b1de-d658452ed578`(画面: Index / Home / Fortune / Profile / Guide / Tarot / Components)。参照用に `docs/design/claude-design/Fortune.dc.html` を保存済み。

## 1. 目的

タロット練習アプリ tarot-everyday に、生年月日を一度入力するだけで7つの占術の結果を一覧できる機能を追加する。メインコンテンツは次の3つ。

1. あなたはどういう人か(人物像)
2. 今日・今月・今年の運勢(初期表示は「今日」)
3. 7占術+1dayタロットを統合した総合鑑定プロンプト(ユーザーが自分で契約しているChatGPTやClaudeなどに貼り付けて使う。既存のタロット占いと同じ方式)

あわせて、アプリ全体のメニューを「ホーム / 運勢 / タロット / 早見表」の4つに再構成し、PCとスマホのレスポンシブ対応を行う。

## 2. 前提と制約

- Next.js 16.2.1(App Router)。`next.config.ts` は `output: "export"`(静的エクスポート)。
  - `next.config` の `redirects`・Route Handler・Server Actions は使えない(`node_modules/next/dist/docs/01-app/02-guides/static-exports.md` の Unsupported Features)。
  - 動的ルートは `generateStaticParams()` で全パスを静的生成する。
- 計算はすべてブラウザ内で行う。生年月日はサーバーに送らない。
- PWA(`public/sw.js`)。オフラインで動作すること。
- 天文計算ライブラリは `astronomy-engine`(MIT)を使う。Swiss Ephemeris は AGPL のため使わない。
- **絵文字は使わない。** 占星術記号(♈ ☉ ☀ ☽ など)のUnicode文字も、端末によって絵文字として表示されるため使わない。記号はすべて自前のSVGパスで描く。
- 書籍などの解説文は流用しない。解説文はすべてオリジナルで書く。

### 3.1 期間の定義

| 占術 | 今日 | 今月 | 今年 | 年の区切り |
|---|---|---|---|---|
| 数秘術 | パーソナルデー | パーソナルマンス | パーソナルイヤー | 1/1 |
| 九星気学 | 日盤 | 月盤 | 年盤 | 立春 |
| 四柱推命 | 日の干支と命式の関係 | 月の干支 | 年の干支+大運 | 立春 |
| 算命学 | 日の干支の星、天中殺の日か | 月の干支の星、天中殺の月か | 年の干支の星、天中殺の年か | 立春 |
| 宿曜 | 日の宿(三九の秘法) | 旧暦の月の宿 | 旧暦の年の宿 | 旧正月 |
| マヤ暦 | 今日のKIN | 13の月の暦の現在の月(28日周期) | 年回りのKIN(今年の誕生日のKIN) | 誕生日 |
| 西洋占星術 | 正午の月の星座と本命のハウス | 暦の月の新月・満月の星座とハウス+火星 | 暦の年の木星・土星の星座とハウス(年内の星座の変化をすべて表示) | 1/1 |

- 「今日」は日本時間の0時で切り替える。
- 各運勢カードには、その占術での期間(例「2026/2/4〜2027/2/3」)を必ず表示する。
- 九星気学の日盤は、冬至・夏至に最も近い甲子の日に陽遁・陰遁を切り替える。
- 九星気学の月盤・年盤は、暦の慣習どおり節入り日・立春の当日(節入りの時刻より前も含む)を新しい月・年に含める。期間の表示は節入り日〜次の節入り日の前日(例: 寒露が 2026/10/8 15:29 なら、2026/10/8 から戌月)。人物像(本命星・月命星)は従来どおり節入りの時刻で区切る。

## 4. 入力と保存

```ts
interface BirthProfile {
  version: 1;
  date: { year: number; month: number; day: number };
  time:
    | { kind: "unknown" }
    | { kind: "half"; half: "am" | "pm" }
    | { kind: "hour"; hour: number } // 0〜23。分は分からない(その時の30分で計算)
    | { kind: "minute"; hour: number; minute: number }; // 0〜23・0〜59
  prefecture?: PrefectureCode; // 47都道府県。未入力なら明石基準
  gender?: "male" | "female"; // 大運の進む向きの判定にのみ使う
}
```

- 自分1人分を localStorage に保存する(キー: `tarot-birth-profile`)。変更と削除ができる。
- `minute` は後から加えた入力方式で、`version` は 1 のまま。分のない `hour` の保存データもそのまま読める。読み込み時と保存時に、時は0〜23・分は0〜59の整数かを確かめる。
- 時刻の表記は、分まで指定なら「14:35」、分不明なら「14時台」(要約の例「1990/3/29 生 · 14:35 · 東京都」)。
- 都道府県ごとに、県庁所在地の緯度と経度を固定値で持つ。
- 都道府県が未入力のときは、明石(東経135°、北緯34.65°)を基準にする。ハウスとASCも明石基準で計算し、画面に「出生地未入力のため明石基準」と注記する。四柱推命の時刻補正は、明石基準なので補正なしと同じになる。
- 性別は「男性 / 女性 / 回答しない」。「大運の計算にのみ使用」と明記する。
- 時刻は日本時間として扱う。1948〜1951年のサマータイム期間に当たる場合は1時間戻して補正する。日付で数える計算(蔵干・二十八元の節入りからの日数、大運の日数)は標準時(UTC+9)の日付を使う。日柱は、時刻を指定したときは補正後の時刻(四柱推命は地方平均時、算命学は標準時)の日付、不明・午前午後のときは入力された誕生日の日付で出す。

## 5. 時刻が曖昧なときの扱い

すべての入力を「生まれた瞬間の範囲」(`BirthMoment`)に変換して扱う。

| 入力 | 範囲 |
|---|---|
| 不明 | 0:00〜23:59 |
| 午前 / 午後 | 0:00〜11:59 / 12:00〜23:59 |
| 時刻を指定(分まで) | その1分(例: 14:35 なら 14:35:00〜14:35:59) |
| 時刻を指定(分は分からない) | その時の30分の1分(例: 14時台なら 14:30:00〜14:30:59) |

`ambiguity.ts` の共通処理:

1. 各占術が `read` の中で求める境界時刻(節入り、立春、朔、時柱の境目、月の星座移動、ASCの星座移動など)で範囲を区切る(`resolveOverRange`)。
2. 区切った各区間の中央の時刻で人物像を計算する。
3. 結果が同じ区間はまとめる。
4. 結果が1つなら「確定」、複数なら「候補」として、時刻範囲付きで返す。

表示例: 「候補: 牡羊座(〜14:20)/ 牡牛座(14:20〜)」(テラコッタ色、先頭に小さな丸)。

例外: 四柱推命の時柱は、時刻を指定したときだけ出す(不明・午前午後で候補を出すと6〜12個になるため)。四柱推命の経度補正も、時刻を指定したときだけかける。西洋占星術の ASC・MC・ハウス・チャート円は、不明なら正午、午前なら6時、午後なら18時で仮計算して出し、値に「(仮)」、運勢に「ハウスは…で仮計算」の注記を付ける(ユーザーの判断)。時刻を指定したときは、分まで指定ならその分ちょうど、分は分からないならその時の30分で計算する。分が分からないときは値に「(仮)」、チャートに「分が不明のため14時30分で計算」、運勢に「ハウスは分が不明のため14時30分で計算」の注記を付ける。天体の星座は出生時刻の範囲で候補にする。

時刻を指定したときの範囲は1分なので、時柱・日柱(地方平均時の0時)・ASC などは、境目を含む1分に生まれたときだけ候補になる。分が分からない時台を30分で計算するのは、1時間の範囲で候補を出すより結果を1つに決めたほうが分かりやすいため(ユーザーの判断)。境目に近い時台の生まれは、分まで入力すれば正確になる。プロンプトの出生時刻は、分まで指定なら「14:35」、分不明なら「14時台(14:30として計算)」と書く。

### 6.2 占術モジュールの共通インターフェース

```ts
type SystemId =
  | "numerology" | "kyusei" | "maya" | "shichu" | "sanmei" | "sukuyo" | "horoscope";
type Period = "day" | "month" | "year";

interface FortuneSystemModule {
  id: SystemId;
  name: string;   // 例: 九星気学
  nameEn: string; // 例: Nine Star Ki
  read(profile: BirthProfile, moment: BirthMoment, today: LocalDate): SystemReading;
}

interface SystemReading {
  id: SystemId;
  name: string;
  nameEn: string;
  method: string;                          // 総合鑑定プロンプトに書く採用方式
  natal: Fact[];                           // 人物像
  periods: Record<Period, PeriodResult>;   // 今日・今月・今年
  ambiguous: boolean;                      // 出生時刻の曖昧さで人物像が分かれたか
  chart?: NatalChart;                      // 人物像の専用の図(四柱推命の命式表・算命学の人体星図・西洋占星術のホロスコープ)
}

interface ElementRef { system: SystemId | "tarot"; id: string } // id は element-ids.ts の ELEMENT_IDS のいずれか

/** 表示用の事実(整形済み) */
interface Fact {
  key: string;        // 占術内で一意の安定した識別子(例: "honmei")。表記が変わっても変わらない
  label: string;      // 例: 本命星
  value: string;      // 候補があれば「A(〜5:01) / B(5:01〜)」
  refs: ElementRef[]; // 早見表の項目
  candidates?: { value: string; rangeLabel: string }[]; // 表記が分かれるときだけ。隣り合う同じ表記はまとめる
}

interface PeriodResult {
  period: Period;
  rangeLabel: string;                         // その占術での期間(例: 2026/2/4〜2027/2/3)
  headline: { text: string; ref: ElementRef }; // 画面側で `${text}。${ref の項目の periodNote}` に組み立てる
  chips: Fact[];
  note?: string; // 例: 本命星を二黒土星として計算(出生時刻により一白水星の可能性があります)
}
```

- 各占術の `read` が、境界時刻での分割(`resolveOverRange`)・人物像の計算・期間ごとの計算をまとめて行い、表示用に整形済みの `SystemReading` を返す。画面は `registry.ts` の `readAll(profile, today)` で全占術の結果を受け取る。
- 運勢(期間の結果)は、人物像が候補に分かれるときは最初の候補で計算し、その前提を `note` に書く。
- `NatalChart` は `{ kind: "pillars"; columns; rows: { label; cells: (Fact | null)[] }[]; factKeys }`(命式表)、`{ kind: "body-stars"; cells: ({ fact; tone: "center" | "main" | "sub" } | null)[]; factKeys }`(人体星図、3×3 を左上から行ごと)、`{ kind: "horoscope"; bodies; asc; mc; cusps: Record<HouseSystem, number[]>; aspects; notes; factKeys }`(ホロスコープ。タイル3つの下に出す)のいずれか。`factKeys` は図が表している人物像の事実で、図があるときは一覧に重ねて出さない。
- 早見表の項目 id は `element-ids.ts` の関数で作り、占術ごとの一覧 `ELEMENT_IDS` に含まれるものだけを使う。

### 6.3 読み込みの軽量化

- `astronomy-engine` と占術モジュールは、`/fortune` とホームの運勢カードでだけ動的に読み込む(`import()`)。

## 7. 早見表の辞書とテンプレート文

```ts
// src/data/guide/types.ts(フェーズ1Bで実装した形)
type GuideSystemId = "tarot" | "numerology" | "kyusei" | "maya" | "shichu" | "sanmei" | "sukuyo" | "horoscope";

type GuideImage =
  | { kind: "glyph"; text: string; color?: string } // 漢字・数字のタイポグラフィ。"\n" で改行(3行まで)
  | { kind: "photo"; path: string; alt: string }    // カード画像など
  | { kind: "astro"; name: AstroGlyphName; color?: string }; // 星座・天体の SVG 記号(src/components/icons/astro-glyph.tsx)

interface GuideEntry {
  system: GuideSystemId;
  id: string;           // ElementRef.id と同じ。URLにも使う。例: "star-1"
  group: string;        // 一覧の見出し。例: 「九星」「太陽の紋章」「大アルカナ」
  name: string;
  reading: string;      // 読み(ひらがな)。タロットは空文字
  nameEn?: string;      // 例: "White Wizard"(Caveat体で表示)
  keywords: string[];   // 3〜5語
  summary: string;      // 人物像としての説明(2〜3文)
  periodNote?: string;  // 運勢として出たときの一文(期間を表す語を含めない)。タロットは持たない
  image: GuideImage;
  related?: string[];   // 同じ占術の関連項目の id
}
```

- 画像の `{ kind: "icon"; symbol: IconId }`(SVGの記号)と、`photo` の `credit`(出典)・`fallbackIcon`(画像がないときの記号)は、星座・天体・十二支の画像を使うフェーズ2以降で追加する。

- 運勢の一文は、「関係を表す要素」の `periodNote` をテンプレートに差し込んで作る。文章の量が組み合わせ数ではなく項目数に比例するようにする。
  - 例(宿曜):「今日の宿は{宿}。本命宿との関係は「{関係}」。{関係.periodNote}」
  - 例(四柱推命):「日干{甲}に対して{丙}は{食神}。{食神.periodNote}」
- 早見表の項目数は全体で約250。

| 宿曜 | 二十七宿、三九の関係(11) |
| 西洋占星術 | 十二星座、天体、ハウス(12)、アスペクト、エレメント |

- `periodNote` を持つのは運勢の見出しで使うグループだけ: 四柱推命は通変星、算命学は十大主星と天中殺、宿曜は三九の関係、西洋占星術はハウス(数秘術・九星気学・マヤ暦は全項目)。

(デザインでは宿曜の関係グループが「六害宿の関係」と表記されているが、正しくは「三九の関係」とする)

### 7.2 画像

- 星座・天体・十二支: Wikimedia Commons のパブリックドメイン画像(『Urania's Mirror』などの銅版画、古典絵画、浮世絵)。タロットと同じく、リポジトリには含めずスクリプトでダウンロードする。CC BY-SA などの素材は使わない。画像がない場合は `fallbackIcon` のSVGを表示する。
- それ以外: 漢字・数字のタイポグラフィ、またはSVGの記号。
- マヤ暦の紋章: ドリームスペルの紋章デザインは著作権があるため使わない。代わりに古代マヤの日の文字(Wikimedia Commons の DaySign シリーズ。パブリックドメイン)の線画を、紋章の色(赤・白・青・黄)で塗って表す。画像がなければ紋章名のタイポグラフィ。
- 天体: 一覧のタイルは記号(ドラゴンヘッドなどと同じ)、シート・詳細ページは絵画・写真(ユーザーの判断)。
- 十二支: 歌川国芳『道化十二支』。一覧のタイルは絵を暗くして漢字を重ね、シート・詳細ページは絵だけを大きく出す(ユーザーがプレビューで選択)。
- 画像の一覧は `src/data/guide/photos.json`・`maya-glyphs.json`、取得は `node scripts/download-guide-images.mjs`(`public/guide-images/` はリポジトリに含めない)。
- 画像とタイポグラフィの混在は、共通の正方形の枠(角丸14px、枠 gold/25%)で統一する。

## 8. 総合鑑定プロンプト

今日・今月・今年の3つの期間をまとめて鑑定してもらう(運勢ページのタブには関係しない)。アプリの解釈文(見出しの一文や早見表の「運勢として出たとき」)は入れず、各占術で求めた要素の値・注記・採用している方式だけを渡して、意味づけと占術間の統合は生成AIに任せる(ユーザーの判断)。1dayタロットもカード名と正逆だけでキーワードは入れない。相談内容に別の期間(例: 来年)や話題があれば、AIが生年月日と方式から要素を求めて追加で鑑定する。

```
東洋・西洋の複数の占術で求めた要素をもとに、相談者の今日・今月・今年の運勢を総合的にわかりやすく鑑定してください。

■ 生年月日: … / 出生時刻: … / 出生地: … / 性別: …
■ 鑑定日: …
■ 相談内容: …(未入力なら「特になし(総合的な鑑定)」)

── 人物像(生まれ持った要素) ──
【占術名】…(候補がある項目は「A または B(出生時刻が曖昧なため候補)」)

── 今日の要素 ── / ── 今月の要素 ── / ── 今年の要素 ──
【占術名】(期間: …)要素: 値 / …
  注記: …

── 今日の1dayタロット ──
…(未抽選なら「未抽選」。「好きな生年月日で占う」ではこの節ごと入れない)

── 採用している方式 ──
…

── 依頼 ──
1. 人物像を、占術間の共通点と矛盾点に触れながら統合して説明する
2. 今日・今月・今年の運勢を、各期間の要素から鑑定する
3. 3つの期間を通した流れと具体的なアドバイス
4. 相談内容を軸にし、別の期間や話題があれば要素を求めて追加で鑑定する
5. 候補や仮計算の項目は不確かさを踏まえて解釈する
```

### 11.4 プロフィール(`/fortune/profile`)

- ヘッダー: 戻るボタン(40px丸)+「プロフィール」+Caveat「Birth data」。
- 項目ごとに、アイコン付きのラベルと「必須 / 任意」の表示。
  - 生年月日(必須): 年(1900〜今年)・月・日のセレクト(比率1.4 : 1 : 1、高さ48px)。存在しない日付は選べないようにする。
  - 出生時刻(任意): セグメント「不明 / 午前・午後 / 時刻を指定」。
    - 不明: 「時刻が不明の場合、時柱・ASC・月星座などは「候補」として時刻範囲付きで表示されます。」
    - 午前・午後: 大きめの2択ボタン(「午前 0:00〜11:59」「午後 12:00〜23:59」)。
    - 時刻を指定: 分まで入力できる時刻入力(`<input type="time" step="60">`、高さ48px)と、チェックボックス「分は分からない(14時台として計算)」(時は入力した時に合わせて変わる)。チェックありは `hour`、なしは `minute` で保存する。切り替えた直後の時刻入力は空にして、入力するまで保存できず「出生時刻を入力してください」と表示する(12:00 などを誤って保存しないため)。登録済みの `hour` を編集するときは、チェックありで HH:30 を表示する。チェックを入れると時刻入力の分を30分にし、チェック中に30分以外を選ぶとチェックを外す(チェックなしで30分を選んでもチェックは入れない)。
  - 出生地(任意): 47都道府県のセレクト。
  - 性別(任意): セグメント「男性 / 女性 / 回答しない」+「大運の計算にのみ使用」。
- 「保存」(プライマリ)、「登録情報を削除」(デンジャー。確認のステップを挟む)、「データは端末内にのみ保存されます」(鍵アイコン)。
- PC: 左にフォーム(520px のカード内。出生地と性別は2列)、右に「この入力で分かること」のプレビュー(実装済みの占術で、入力内容から分かる結果と、時刻の入力方式によって何が候補になるかを表示)。

### 11.5 早見表(`/guide`、`/guide/[system]/[id]`)

- グループごとに「グループ名+項目数」と、正方形タイルのグリッド(スマホ4列、PC10列。PCでサイドパネルを開いて一覧の幅が680px未満になったときは8列)。
- タイル(検索結果も)を押すと、ページを移らずに詳細シートで開く(1280px未満はボトムシート、1280px以上は右のサイドパネル)。中身は運勢ページのシートと同じ(画像・名前・読み・英名・キーワード・説明・「運勢として出たとき」。タロットは正位置・逆位置のタブ)で、末尾のリンクは「詳しく見る」(運勢ページから開いたときは「早見表で見る」)。一覧のスクロール位置は変えない(パネルの開閉で一覧の幅が変わっても、押したタイルを同じ位置に保つ)。
- 詳細ページの戻るボタン: 早見表の中(シートの「詳しく見る」・関連項目)から来たときはブラウザの「戻る」と同じにし、一覧をスクロール位置ごと戻す。URLを直接開いたとき・新しいタブ・運勢ページから来たときは `/guide?tab={占術}` へ移る。判定は、早見表の中のリンクを押したときにメモリに印を立て、詳細ページの表示時にその履歴エントリーの `history.state` に記録する(`src/lib/guide-back.ts`)。
- 詳細ページ(URLを直接開く・共有・関連項目・画像の出典のため残す。関連項目のタイルは詳細ページへのリンク):
  - スマホ: 戻るボタン+パンくず(「早見表 / 四柱推命 / 十干」)、220pxの画像枠(内側にもう一重の枠)、名前30px、読み、英名(Caveat)、キーワードバッジ、説明、関連項目(4列のタイル)。
  - PC: 左に360pxの画像、右に名前(36px)+記号、読み(星座は期間も)、英名、キーワード、説明(最大幅520px)、関連項目。

### 11.6 タロット(`/tarot`)

- 見出し(Caveat「Tarot」+「タロット」+区切り線+「今日はどちらにしますか」)。

### 11.7 好きな生年月日で占う(`/fortune/other`)

- 家族や友人など、プロフィールに登録していない生年月日の運勢と人物像を見るページ。ホームの入口カードから開く。ナビは「運勢」を選択中にする。
- ヘッダー: 戻るボタン(40px丸、ホームへ)+「好きな生年月日で占う」+Caveat「Any birthday」。
- 入力欄はプロフィール入力(§11.4)と同じ部品(`BirthFields`)を使う。初期値は生年月日が今日(日本時間)、出生時刻が不明、出生地が東京都、性別が回答しない。カードの中に置き、PC(1024px〜)では4項目を2列に並べる。下に「入力した内容は保存されません」(鍵アイコン)。
- 保存はしない。入力はページの中だけで持ち、再読み込みで初期値に戻る。`tarot-birth-profile` には触れない。
- 「今日」はクライアントで分かってから入力欄を表示し、その値で初期値を決める(静的書き出しのビルド時の日付を使わない。サーバー描画とハイドレーションの間は読み込み中の枠を出す)。
- 結果は運勢ページ(§11.2)の本体と同じ(期間タブ、占術ごとの運勢カード、人物像、総合鑑定プロンプト)を、入力を変えるたびにその場で計算し直して表示する(保存ボタンはない)。1dayタロットは表示せず、総合鑑定プロンプトにも入れない。人物像の見出しは「この生年月日の人物像」(Caveat「About this birthday」)。
- 生年月日が揃っていない・時刻を指定して未入力・未来の日付のときは、結果の代わりに案内を表示する。
- PCのレイアウトは運勢ページと同じ(本文の幅が56rem以上なら2カラム)。計算エンジンは運勢ページと同じく動的に読み込む。

## 12. テスト

- 暦エンジン: 国立天文台が公表している二十四節気と朔の時刻と照合する(誤差1分以内)。
- 各占術: 参照サイトや書籍の値を使った固定テストケース(1占術あたり10件以上)。
- 曖昧さの処理: 立春当日、節入り当日、23時台、サマータイム期間などの境界ケース。
